## 4. The commentator bank

- **Count and format:** 340 lines.
  - Converted outside the engine with ffmpeg (soxr) from the VOX2 48 kHz WAVs to **mono 24 kHz 16-bit**. No gain change, so the bank stays at -18 LUFS / -1.5 dBTP.
  - Imported as `/JamAssets/Audio/VO/VO_Commentator_<id with dots as underscores>`: compression quality 40, `SC_VO`, not looping, no attenuation (2D).
- **Loading behaviour:**
  - Every wave is set to **`LoadOnDemand`** (`SoundWaveLoadingBehavior.LOAD_ON_DEMAND`, read back after the save).
  - UE 5.9 has no separate "streaming" check box any more: the loading behaviour is the switch, and stream caching is always on. In practice a line's compressed audio is fetched when it is played and released after.
  - Nothing is held in memory until a line plays, so the first play of a line may start a few ms late (not measured).
  - If all 340 were resident: about 2 to 4 MB compressed (Bink q40 estimate in section 6), or 29.4 MB as PCM (611.8 s x 24 kHz x 2 bytes).
- **`SC_VO`:** it has no parent class, like `SC_SFX` / `SC_Music` / `SC_Ambience` (none of the existing classes has a parent; there is no master class in the project).
  - It has a volume adjuster in `SCM_Volume` (4 classes now).
  - It carries a **passive mix `SCM_DuckMusic`**: `SC_Music` x 0.45, fade in 0.15 s, out 0.6 s, applied while any `SC_VO` sound plays.
  - Measured on `MS_music_match`: **-6.9 dB while a line plays**, back to 0 dB about 0.6 s after it ends.
- **Table or JSON: JSON.**
  - `Game/Source` has **no `FTableRowBase` struct at all**. The bark bank (`FJamBarkLine` in `BarkSystem.h`) is a plain `USTRUCT` parsed from embedded JSON, and its fields (Situation, Speaker, Tone) do not fit. So there is no `DT_Commentary`.
  - The manifest is `Game/Plugins/JamAssets/Content/Audio/VO/commentary.json`, schema `hokej.commentary/1`, 121,726 bytes.
  - Each line has `id`, `event`, `kind` (empty = any Kind), `team` (`blue` / `orange` / `any`), `priority` (1..5), `cooldown_s`, `when` (copied from `briefs/commentary/lines.json`), `text`, `sound` (the full object path of the wave) and `seconds`.
  - **Device A must add `JamAssets/Content/Audio/VO` (or just this file) to the staged non-asset files** (`DirectoriesToAlwaysStageAsNonUFS` or `+DirectoriesToAlwaysStageAsUFS` in `DefaultGame.ini`, A's file). Otherwise the packaged game has the waves but no manifest.
  - The waves are referenced only by path strings, so **the cook will not pick them up by reference either**. A must also add `/JamAssets/Audio/VO` to `DirectoriesToAlwaysCook`, or load them through an asset registry scan. Alternative: A defines a row struct and B rebuilds `DT_Commentary` from this JSON (a CSV import is about one minute of editor time).
- **How device A looks a line up:**
  1. Parse the JSON once and index by `event`.
  2. Candidates: `kind` empty or equal to the payload Kind; `team` `any` or the colour of the event's team (team 0 = blue, 1 = orange); `when` holds (README section 4).
  3. Then play `sound` through `MS_commentary`: spawn 2D, `SetWaveParameter("Line", wave)`, optionally `SetFloatParameter("Volume", v)`, `Play()`. Playing the wave directly with `PlaySound2D` also works and also ducks, because the class is on the wave.
- **Runtime rules A's player needs** (from `briefs/commentary/README.md` section 3):
  - **Priority:** the highest `priority` wins (5 = must play: goals, wins, Director's Call; 1 = filler). On a tie, the more specific situation wins (a kind, a colour, a score or clock condition), then a random alternate.
  - **Cooldown:** `cooldown_s` is per **situation**, meaning the id without its `.<nn>`. Never repeat the same line twice in a row (better: none of the last three of that situation).
  - **Never two lines at once:** at most one voice line every 2.5 s, counted from the start of the last line. If the gate is closed, **drop** the line, never queue it. Also never start a line while one is playing: 71 quick lines were long, and one, `lift.clean.01`, is still 2.52 s.
  - **Quick-play and stoppage kinds:** 287 quick-play lines (median 1.66 s) are live calls and must be dropped when late. 53 stoppage lines are full sentences that fit the pauses: events `period`, `period_end`, `season_take`, `win`, `lose` and situation `goal.pause.*`.
  - **Two-beat goal:** first the colour call (`goal.blue` / `goal.orange`), then one score-state or mood line when the gate reopens inside the goal pause.
  - **Events the bank assumes but C-0003 lacks:** `save`, `post`, `breakaway`, `carry`, `period_end`, `clock`, `season_take`. Their lines stay silent until A emits them.
  - Director lines are not in this bank (R-0021: menu and Designer only).
- **Ten lines played** through `MS_commentary` in PIE: `faceoff.drop.01`, `shot.blue.01`, `save.any.01`, `goal.blue.01`, `check.blue.01`, `foul.behind.01`, `pickup_take.blue.01`, `directors_call.any.01`, `period_end.any.01`, `win.any.01`.
  - All ten components spawned and played. The recording has speech at every start (peaks -10.2 to -12.7 dBFS), -24.9 LUFS overall.
