# Unreal MCP: enable, start, connect, test

Measured on 2026-11-11 against UE 5.9.0 (CL 60351404, launcher install at `C:\Program Files\Epic Games\UE_5.9`)
with a throwaway blank C++ project (deleted afterwards). Everything here is tooling; no game content.

Files in this folder:

| File | What |
|---|---|
| `mcp.mjs` | dependency-free Node client for the editor's MCP server: `wait`, `list`, `toolsets`, `describe`, `tools`, `call`, `raw`, `inventory` |
| `mcp.json.template` | the `.mcp.json` Claude Code needs; identical to what the editor's Generate Client Config writes |
| `TOOLS.md` | tool inventory (106 toolsets, 1871 tools) generated by `node tools/mcp/mcp.mjs inventory --out tools/mcp/TOOLS.md` |

Scripts that use it are in `tools/run/` (see the end of this file).

## 1. Enable

In the `.uproject`:

```json
"Plugins": [
  { "Name": "ModelContextProtocol", "Enabled": true },
  { "Name": "ToolsetRegistry", "Enabled": true },
  { "Name": "AllToolsets", "Enabled": true }
]
```

`ModelContextProtocol` is enabled by default in 5.9 but has no toolsets without `ToolsetRegistry`; `AllToolsets` pulls in
41 toolset plugins. Their dependencies (`PythonScriptPlugin`, `EditorScriptingUtilities`, `FileSandbox`,
`DataValidation`, `EngineAssetDefinitions`) are enabled automatically. Engine association for the launcher build:
`"EngineAssociation": "5.9"` (matches `AppName "UE_5.9"` in `C:\ProgramData\Epic\UnrealEngineLauncher\LauncherInstalled.dat`).
The 5.9 C++ template uses `BuildSettingsVersion.V8` and `EngineIncludeOrderVersion.Unreal5_9` in the target files.

## 2. Start the server without clicking

The server does **not** start by default (`bAutoStartServer = false`). Two ways, both proven:

- command line: `UnrealEditor.exe <project>.uproject -nosplash -ModelContextProtocolStartServer`
  (`-StartModelContextProtocolServer` still works but logs a deprecation warning);
- config, `Config/DefaultEditorPerProjectUserSettings.ini` of the project:

  ```ini
  [/Script/ModelContextProtocol.ModelContextProtocolSettings]
  bAutoStartServer=True
  ServerPortNumber=8000
  ServerUrlPath=/mcp
  ```

  (the settings class is `config=EditorPerProjectUserSettings`; the editor UI writes the same key to
  `Saved/Config/WindowsEditor/EditorPerProjectUserSettings.ini`).

Other switches and commands (from the plugin source):

| What | How |
|---|---|
| port | `-ModelContextProtocolPort=N` (overrides the setting) |
| start / stop from the console | `ModelContextProtocol.StartServer [port]`, `ModelContextProtocol.StopServer` |
| rebuild the tool list | `ModelContextProtocol.RefreshTools` |
| write a client config | `ModelContextProtocol.GenerateClientConfig <ClaudeCode/Cursor/VSCode/Gemini/Codex/All>` (a cheat command; works through `-ExecCmds=` or the ConsoleToolset) |
| expose every tool natively | `bEnableToolSearch=False` in the same ini section (default True: `tools/list` shows 4 meta-tools) |
| keep transmitted images on disk | `bDumpMediaToDisk=True` (writes to `Saved/ModelContextProtocol`) |
| server in a commandlet (cook) | never from config; only with `-ModelContextProtocolStartServer`, so a cook does not fight the editor for the port |

Use `tools/run/editor.ps1`, which passes `-ModelContextProtocolStartServer` and waits for the server.

Timings on this machine (RTX 4090, 16 threads, 63 GB): first editor start of a fresh project to MCP ready **43.5 s**
(server listening at 41 s after process start); warm start **about 10 s** to listening.

## 3. Connect Claude Code

Copy `mcp.json.template` to the project root as `.mcp.json`:

```json
{ "mcpServers": { "unreal-mcp": { "type": "http", "url": "http://127.0.0.1:8000/mcp" } } }
```

This is byte-for-byte what `ModelContextProtocol.GenerateClientConfig ClaudeCode` wrote into the project root (verified;
for an installed engine the file goes to the project dir, for a source build to the engine root dir). Server name
`unreal-mcp`, transport Streamable HTTP, no authentication, loopback only.

`claude mcp list` run in that folder lists the server as `unreal-mcp: http://127.0.0.1:8000/mcp (HTTP) - Pending approval`.
A project-scope `.mcp.json` must be approved once in an interactive `claude` session in that folder (trust dialog);
`"enabledMcpjsonServers": ["unreal-mcp"]` in `.claude/settings.local.json` alone did **not** clear the pending state for
a folder that was never trusted. Do the approval once at H0 on each device.

## 4. Test

```
node tools/mcp/mcp.mjs wait --timeout 300                 # initialize until it answers
node tools/mcp/mcp.mjs list                               # 4 meta-tools
node tools/mcp/mcp.mjs toolsets                           # list_toolsets (text: "- Name: description")
node tools/mcp/mcp.mjs describe EditorToolset.LevelToolset
node tools/mcp/mcp.mjs tools EditorToolset.LevelToolset.AddToSceneFromClass     # input/output schema
node tools/mcp/mcp.mjs call EditorToolset.LevelToolset.FindActors '{"filter":{"name":"Cube"}}'
node tools/mcp/mcp.mjs inventory --out tools/mcp/TOOLS.md
```

Exit codes: 0 pass, 1 tool/protocol error (server answered, e.g. `isError`), 2 unreachable, 3 timeout or truncated
answer. The last stdout line is always `{"tool":"thirdjam.mcp/1","verdict":...}`. From PowerShell 5.1 pass arguments as
`@file.json` (PowerShell strips double quotes inside native-command arguments).

Calls proven through MCP (each from a new session; about 1.1-1.4 s per CLI call, of which ~0.3 s per round trip):

| Step | Tool | Result |
|---|---|---|
| spawn | `EditorToolset.LevelToolset.AddToSceneFromClass` `{actorType:{refPath:"/Script/Engine.StaticMeshActor"}, name, xform}` | ok, returns `refPath` |
| spawn from asset | `EditorToolset.LevelToolset.AddToSceneFromAsset` `{assetPath:"/Engine/BasicShapes/Cube.Cube", name, xform}` | ok |
| read back | `EditorToolset.LevelToolset.FindActors` `{filter:{name:"TJ_"}}`, `EditorToolset.ActorToolset.GetLabel` | ok: label, class, bounds, path |
| camera | `EditorToolset.EditorAppToolset.FocusOnActors` `{actors:[{refPath}]}` | ok |
| screenshot | `SceneCaptureToolset.SceneCaptureToolset.CaptureActiveEditorView` `{mode:"Lit", options:{width:1280,height:720}}` | ok, PNG returned as an MCP image block (5 s); `call --save-images <dir>` writes it |
| automation test | `AutomationTestToolset...DiscoverTests {}` (2.4 s), `ListTests {nameFilter}`, `RunTests {testNames:[...]}` | ok, `{passed:1, failed:0}` |
| console | `ConsoleToolset.ConsoleToolset.RunConsoleCommand {command}` | ok (refuses anything containing the word `py`) |
| console output | `ConsoleToolset.LogsToolset.GetLogEntries {logCategory, pattern, maxEntries}` | ok |
| long call | `SceneCaptureToolset...RecordViewport {options:{source:"EditorViewport"}, durationSeconds:35}` | ok after 36.4 s, no server timeout |
| Live Coding | `LiveCodingToolset...CompileLiveCoding {}` after a .cpp change | ok, "Live coding succeeded" in 11.6 s |
| client timeout | same recording with `--timeout 10` | exit 3 `timeout`, editor kept answering |

## 5. Failure modes we hit

1. **Server not running**: forgot `-ModelContextProtocolStartServer` / `bAutoStartServer` (default off). `wait` returns
   `unreachable` (`ECONNREFUSED`).
2. **Modal dialog blocks start-up**: the editor sat on a "Message" box (here: a FileSystem DDC path longer than 119
   characters). The process is alive, the log stops, MCP never answers. `editor.ps1 -WaitMcp` reports the dialog title;
   read the editor log. Keep project paths short.
3. **Empty arguments refused**: a tool whose schema has a required field fails with `isError: Function "X", input params
   are required by the function input schema Json, but incoming function input params Json is empty.` Read
   `describe_tools` first; every argument object is checked against the schema (`additionalProperties:false`).
4. **Tool names**: `describe_toolsets` returns full names `Module.Toolset.Tool`; `call_tool` wants
   `toolset_name = Module.Toolset`, `tool_name = Tool` (split at the last dot). `mcp.mjs call` does this.
5. **`list_toolsets` is text, not JSON** (`- Name: description` lines, descriptions can contain more `- ` bullets);
   `describe_toolsets` and `describe_tools` return JSON inside a text block (`structuredContent` for normal tools).
6. **Node 24 on Windows**: `fetch` keeps sockets pooled and `process.exit` then dies with
   `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c` (exit 127). `mcp.mjs` uses `node:http`
   with no keep-alive instead.
7. **Graceful stop**: closing the editor with an unsaved (template) level raises a save prompt; `editor.ps1 -Stop`
   waits `-StopGraceSec` then force-stops its own process tree. Save or discard through MCP before stopping when it matters.
8. **One call at a time on the game thread**: calls are serialized; an editor that is minimized/unfocused ticks slower,
   which adds latency per request (~0.3 s per round trip measured).
9. **Live Coding** uses Unreal Build Accelerator with a cache in `C:\ProgramData\Epic\UbaCli` (capacity 20 GB):
   count it in the disk budget.
10. `UnrealTraceServer.exe` is launched by the editor and outlives it (detached). It is small; scripts leave it alone.

## 6. Where reality differed from Epic's page

- The page says the server is controlled by "Auto Start Server"; it is off by default for a project-launched editor, and
  the command-line switch `-ModelContextProtocolStartServer` (not on the page) is the scriptable way.
- `initialize` negotiated protocol `2025-11-25` although the plugin's newest setting is `2026-07-28` (the client asked
  for 2026-07-28 first; the server answered with 2025-11-25).
- `tools/list` shows only 4 meta-tools by default (tool search); the toolsets are reached via `call_tool`.
- `list_toolsets` listed 112 entries but 6 (`Graph`, `Node`, `Pin`, twice) are bullet lines from descriptions, so 106
  real toolsets; `AllToolsets` names 41 plugins, which register 106 toolsets with 1871 tools.
- Long calls (36 s) were not cut by the server; the limit is the client's timeout.

## 7. Scripts (`tools/run/`, PowerShell 5.1, exit 0 pass / 1 fail / 2 could not run, JSON line last)

| Script | Does |
|---|---|
| `build.ps1 -Project <p> [-Config Development/Shipping] [-Target Editor/Game]` | UBT build; Shipping means the Game target (the editor target has no Shipping) |
| `editor.ps1 -Project <p> [-WaitMcp] [-Watch [-MaxRestarts 5 -PauseSeconds 15 -MaxHours 100]] [-Stop]` | start the editor with MCP on; watchdog restarts only the editor it started (PID + start time in `logs/editor.json`); `-Stop` writes `logs/editor.stop` then closes it |
| `smoke.ps1 -Project <p> [-SkipBuild] [-KeepEditor]` | build, editor, MCP wait, `tools/list`, `list_toolsets`, spawn + read back + delete an actor, stop |
| `package.ps1 -Project <p> -Out <dir> [-Config Development/Shipping] [-Zip -Name Team_Game] [-Map /Game/...]` | BuildCookRun Win64, sizes, ten largest folders/paks, PASS under 1000 MB, WARN at 900 MB |
| `run-packaged.ps1 -Exe <exe> [-Seconds 10]` | runs the packaged game with `-log`, checks it stays up, stops only that tree |

Measured with these scripts on the blank C++ project (2026-11-11, empty map `/Engine/Maps/Entry`, pak + IoStore,
plugins as in section 1):

| Step | Time | Size |
|---|---|---|
| `build.ps1` editor target, first build (no PCH) | 64.6 s | project 36 MB after build |
| `build.ps1` incremental / Shipping game target after a package | 10.1 s / 4 s | |
| `editor.ps1 -WaitMcp` first start / warm start | 43.5 s / 10.5 s | |
| `package.ps1 -Config Development` (cook 96 s with a fresh project DDC) | 134.6 s + zip 37 s | staged 1020 MB (exe 347 MB, pdb 339 MB, paks 203 MB); **zip 483.5 MB** |
| `package.ps1 -Config Shipping -nodebuginfo` (cook 38 s, DDC warm) | 96.5 s + zip 15 s | staged 465.7 MB (exe 177 MB, paks 203 MB, prereq redist 29 MB); **zip 316.4 MB** |
| `run-packaged.ps1 -Seconds 10` | Development and Shipping both stayed up and were stopped | |
| `smoke.ps1` end to end (build, editor, MCP, spawn/read/delete, stop) | 55 s | |

The empty-map Shipping zip (316 MB) is the "engine" slice of the size budget. Of the 188 MB `.ucas`, about 130 MB is
shader bytecode: global SM6 99 MB, project SM6 17 MB, and SM5 16 MB (D3D11 fallback). Dropping SM5 from
`D3D11TargetedShaderFormats` saves the last part if the D3D11 fallback is not needed.

Disk floor: every script refuses to start, and stops its own child, when free space on the project drive falls below
`-MinFreeGB`, else `$env:TJ_MIN_FREE_GB`, else **20 GB**. Logs go to `<project>\logs\`.
From Git Bash, set `MSYS_NO_PATHCONV=1` before passing `/Engine/...` or `/Game/...` paths (Git Bash rewrites them;
`package.ps1` repairs `-Map` and warns).

## 8. Animation and physics

Proven on a throwaway project (2026-11-11, UE 5.9.0), details and exact calls in two files:

- `ANIMATION.md`: mannequin content from the engine's own template packs (no download); Animation Blueprint with a
  state machine (MCP for everything except adding states and transitions, which needs a small C++ editor helper,
  source included); Control Rig with a procedural node (MCP only); IK retarget UE4 -> UE5 mannequin (one Python script,
  no MCP toolset exists); Blueprint pawn with a capsule and a C++ component leaning from Tick (MCP only, Graph DSL);
  Niagara system from a template on an actor with a screenshot (MCP only); a verdict per skater track.
- `PHYSICS.md`: Chaos sphere with a physical material and an impulse gives identical positions at frames 60/120/180
  across PIE runs and an editor restart **only with Use Fixed Frame Rate = 60**; without it, a background editor steps
  0.33 s per frame. The setting needs a restart (or a Python line) to reach the running editor, and it also cuts MCP
  call latency from about 1.2-1.7 s to 0.06-0.3 s.
