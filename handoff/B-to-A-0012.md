## What

`dev-b` 40c0acd adds `NS_<event>` / `MS_<event>` for `poke`, `lift`, `foul`, `pass`, `effect_start`, `effect_end`, `zone_enter`, `zone_exit` (effect and sound),

(`User.Strength`, `User.Colour`; MetaSound float `Strength`; one-shots that end themselves). Detail: `status/B3b-report.md`.

Where an event's `Kind` changes the picture or the sound, B made **one asset with one extra input** instead of an asset per kind. The binder (lane A5) sets it:

- Niagara: user parameter **`User.Variant`** (float). MetaSound: float input **`Variant`**. Default 0, so a binder that sets nothing gets the first kind.

| Event | `Kind` -> `Variant` |
|---|---|
| `poke` | `clean` 0, `miss` 1 |
| `faceoff` | `drop` 0, `won` 1, `lost` 2 |
| `foul` | `foul_from_behind` 0 (single whistle), `foul_no_puck` 1 (double whistle); 2 is a long whistle with a buzzer, free for a harder foul if a ruling adds one |
| `signal` | `defend` 0, `space` 1, `pass` 2, `praise` 3 (B's reading of the four signal intents; give B the real list and order if it differs) |

Three more things the binder must do for these to read right:
1. `bark`, `signal` and `announce` are **2D** sounds (UI blips and a sting), not positioned at `Where`.
2. `zone_enter` / `zone_exit` carry the zone **id** in `Kind`: the binder passes the zone kind's colour as `User.Colour` (B proposes: `slow_ice` (0.35, 0.65, 1.0),
   `fast_ice` (0.2, 1.0, 0.8), `bumper` (1.0, 0.35, 0.1), `no_shoot` (1.0, 0.1, 0.2), `boost_only` (0.9, 0.8, 0.2); the same colours will be on B's zone strip materials).
3. `pass` sends `Strength` as speed / `game.puck.max_speed` (0..1), not m/s.

## Why

A misnamed or missing parameter is silent. `Kind` is an `FName` in the payload; Niagara and MetaSounds take numbers, so the mapping has to be written down once.
`period` (in the event header of C-0003, `Kind = take_<n>`) has no sound: say if it should have one.
