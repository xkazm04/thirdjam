## What

Make `tools/run/common.ps1` (dot-sourced by `build.ps1`, `package.ps1`, `smoke.ps1`) set the engine's bundled x64 .NET in the environment when the
host is ARM64, so the scripts work on device B without a machine-level setting. Device B is a Windows 11 ARM64 machine (NVIDIA N1X); the editor and
the toolchain run as x64 under emulation.

## Why

On B, `tools/run/build.ps1` exits -2147450730 after 2 s with an empty log. `Engine/Build/BatchFiles/GetDotnetPath.bat` picks `win-arm64` when
`PROCESSOR_ARCHITECTURE` is `ARM64`, but the launcher engine ships only `Engine/Binaries/ThirdParty/DotNet/10.0/win-x64`; `dotnet` falls through to
the system .NET 8 runtime and UnrealBuildTool (.NET 10) cannot start. `RunUAT.bat` calls the same batch file, so packaging is affected too.

Proven workaround on UE 5.8.4 (build passed in 98.5 s, editor and MCP came up in 48.7 s): the batch file skips its selection when
`UE_DOTNET_VERSION` is already `10.0`, so setting the variables first is enough. Until this lands, B sets them at user level; nothing is blocked.

Proposed addition to `common.ps1`, after `Get-EngineRoot` (the `10.0` folder is from 5.8; check it on 5.9):

```powershell
# Windows on ARM64: the launcher engine has no win-arm64 .NET; force the bundled x64 one (runs emulated).
function Set-EngineDotnet {
    param([string]$Engine)
    if ($env:PROCESSOR_ARCHITECTURE -ne 'ARM64' -or $env:UE_DOTNET_VERSION) { return }
    $root = Join-Path $Engine 'Engine\Binaries\ThirdParty\DotNet'
    $ver = Get-ChildItem $root -Directory -ErrorAction SilentlyContinue | Sort-Object Name -Descending | Select-Object -First 1
    if (-not $ver) { return }
    $d = Join-Path $ver.FullName 'win-x64'
    if ((Test-Path (Join-Path $ver.FullName 'win-arm64')) -or -not (Test-Path $d)) { return }
    $env:UE_DOTNET_VERSION = $ver.Name; $env:UE_DOTNET_ARCH = 'win-x64'; $env:UE_DOTNET_DIR = $d; $env:DOTNET_ROOT = $d
    $env:DOTNET_MULTILEVEL_LOOKUP = '0'; $env:DOTNET_ROLL_FORWARD = 'LatestMajor'; $env:PATH = "$d;$env:PATH"
}
```

called once with the engine root in `build.ps1` and `package.ps1`. It does nothing on device A (`PROCESSOR_ARCHITECTURE` is `AMD64`).
